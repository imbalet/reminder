# Reminder

Система управления напоминаниями с микросервисной архитектурой, поддержкой нескольких методов доставки и асинхронной обработкой событий. Реализованы авторизация и аутентификация пользователей, централизованная валидация JWT, управление каналами доставки и напоминаниями.

> На данный момент функционал метода доставки `Email` реализован частично, без реальной отправки. Основной функционал - добавление, удаление и привязка к напоминаниям работает.

## Функционал

- Регистрация, аутентификация при помощи JWT токенов
- Создание текстовых напоминаний 
- Управление методами доставки напоминаний
- Получение напоминаний в Telegram

## Стек

- Python 3.12
- FastAPI - API фреймворк
- Aiogram - Фреймворк для Telegram бота
- PostgreSQL
- SQLAlchemy - ORM
- Alembic - Миграции базы данных
- Redis - Хранение временных данных
- RabbitMQ (aio-pika) - Брокер сообщений

## Архитектура

Приложение состоит из 5 микросервисов:

- [**API Gateway**](./api-gateway/README.md)  
  Центральная точка входа в систему. Проверяет и валидирует JWT-токены через JWKS-эндпоинт Auth Service, а затем проксирует запросы к остальным сервисам. Добавляет в запросы идентификатор пользователя, чтобы сервисы не дублировали логику авторизации.

- [**Auth Service**](./auth-service/README.md)  
  Сервис отвечает за регистрацию и аутентификацию пользователей. Реализует JWT-аутентификацию с access/refresh токенами, ротацией ключей и JWKS-эндпоинтом. Хранит refresh-токены и выпускает новые при обновлении сессии. В автоматическом режиме проводит ротацию ключей.

- [**User Service**](./user-service/README.md)  
  Управляет информацией о пользователях и их методах доставки напоминаний (Telegram, Email). При регистрации получает данные от Auth Service через RabbitMQ. Также работает с системными уведомлениями (например, при ошибке доставки или если все методы доставки напоминания удалены).

- [**Reminder Service**](./reminder-service/README.md)  
  Управляет напоминаниями пользователей: создаёт, обновляет и отправляет их в очередь на обработку. При изменении методов доставки в User Service синхронизирует свои данные о них.

- [**Send Service**](./send-service/README.md)  
  Подписывается на очередь напоминаний в RabbitMQ и отвечает за их отправку пользователям. Поддерживает доставку в Telegram, а также обрабатывает сценарии, когда метод недоступен (например, Email без сервера).

- [**Confirm Service**](./confirm-service/README.md)  
  Используется для подтверждения Telegram как метода доставки. Генерирует и хранит в Redis коды подтверждения, которые пользователь вводит в User Service для привязки Telegram-чата.

## Запуск

### Конфигурация


В файле `.env` в корне проекта нужно указать следующие переменные окружения:

| Переменная                         | Пример                                     | Описание                                                                             |
| ---------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------ |
| `APP_PORT`                         | `8000`                                     | Порт, по которому приложение будет доступно на хосте                                 |
| `LOG_LEVEL`                        | `INFO`                                     | Уровень логирования приложения (DEBUG/INFO/WARNING/ERROR/CRITICAL)                   |
| `TG_BOT_TOKEN`                     | `<your_token>`                             | Токен Telegram-бота                                                                  |
| `DB_USER`                          | `postgres`                                 | Имя пользователя PostgreSQL                                                          |
| `DB_PASS`                          | `<your_password>`                          | Пароль пользователя PostgreSQL                                                       |
| `REDIS_PASSWORD`                   | `<your_password>`                          | Пароль Redis                                                                         |
| `RMQ_USER`                         | `guest`                                    | Имя пользователя RabbitMQ                                                            |
| `RMQ_PASS`                         | `<your_password>`                          | Пароль пользователя RabbitMQ                                                         |
| `RMQ_DLQ_FAILED_REMINDERS_NAME`    | `user-service.failed_reminders.dlq`        | Название dead letter queue RabbitMQ для ошибок отправки напоминаний                  |
| `RMQ_DLX_FAILED_REMINDERS_NAME`    | `failed_reminders.dlx`                     | Название обменника для DLQ RabbitMQ                                                  |
| `RMQ_USER_ADD_QUEUE`               | `user-service.users.add`                   | Название очереди событий регистрации пользователей                                   |
| `RMQ_DELIVERY_METHOD_ADD_QUEUE`    | `reminder-service.delivery_methods.add`    | Название очереди для публикации событий добавления метода доставки                   |
| `RMQ_DELIVERY_METHOD_REMOVE_QUEUE` | `reminder-service.delivery_methods.remove` | Название очереди для публикации событий удаления метода доставки                     |
| `RMQ_REMINDER_DEACTIVATE_QUEUE`    | `user-service.reminder.deactivate`         | Название очереди для обработки деактивированных напоминаний                          |
| `RMQ_REMINDERS_QUEUE`              | `reminders.send`                           | Очередь для отправки напоминаний                                                     |
| `ALGORITHM`                        | `RS256`                                    | Алгоритм подписи JWT токенов. Поддерживается только `RS256`                          |
| `ACCESS_TOKEN_EXPIRE_MINUTES`      | `15`                                       | Срок действия access token в минутах                                                 |
| `REFRESH_TOKEN_EXPIRE_DAYS`        | `7`                                        | Срок действия refresh token в днях                                                   |
| `KEY_PAIR_EXPIRES_DAYS`            | `15`                                       | Срок действия пары ключей для подписи JWT в днях                                     |
| `ROTATING_BEFORE_EXPIRING_DAYS`    | `2`                                        | Время в днях, за которое до истечения срока действия пары ключей выполняется ротация |
| `AUTH_SERVICE_DB`                  | `users`                                    | Название базы данных для auth-service                                                |
| `USER_SERVICE_DB`                  | `user-profiles`                            | Название базы данных для user-service                                                |
| `REMINDER_SERVICE_DB`              | `reminders`                                | Название базы данных для reminder-service                                            |
| `POSTGRES_DATABASES`               | `user-profiles users reminders `           | Список всех создаваемых баз данных                                                   |

Для конфигурации можно воспользоваться файлом `.env.example`, заполнив только переменные `RMQ_PASS`, `REDIS_PASSWORD`, `DB_PASS`, `TG_BOT_TOKEN`.  
Необходимо создать бота в Telegram и получить токен при помощи [BotFather](https://t.me/BotFather).  

### Docker compose

Убедитесь, что у вас установлены [Docker](https://www.docker.com/) и [Docker Compose](https://docs.docker.com/compose/).  

Сборка и запуск проекта:

```bash
docker compose up -d --build
```

Остановка и удаление контейнеров:

```bash
docker compose down
```  

### Локальный запуск

Для локального запуска необходимо иметь развернутые локально или в контейнере RabbitMQ, Redis и PostgreSQL (опционально, в зависимости от типа запуска сервисов).  
Инструкции по запуску находятся в файлах `README.md` в каждом модуле.   

## Структура проекта

```bash
.
├── api-gateway             # API gateway сервис
├── auth-service            # Auth сервис
├── confirm-service         # Confirm сервис
├── initdb                  # Скрипты для корректной инициализации базы данных
├── reminder-service        # Reminder сервис
├── send-service            # Send сервис
├── user-service            # User сервис
├── docker-compose.yml
├── Dockerfile              # Dockerfile для автоматической инициализации базы данных
└── README.md
```

Проект включает в себя 5 микросервисов, каждый из которых представляет собой отдельный python пакет.  
В директории для каждого микросервиса есть файл `README.md` с подробным описание работы и запуска сервиса или тестов для него.  

В корне проекта находится директория `initdb`, в которой находится bash скрипт для создания баз данных для всех сервисов.
`Dockerfile` использует образ PostgreSQL и скрипт инициализации для дальнейшего запуска и инициализации базы данных из docker compose.
